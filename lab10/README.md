# Лабораторная работа №10: СМО с усложнениями (Методы ООП)

Реализация системы массового обслуживания (СМО) многоканального типа (M/M/c) с **двумя дополнительными усложнениями**.

## Реализованные усложнения

В данной лабораторной работе реализована система M/M/c/K с нетерпеливыми заявками:

1. **Ограниченная очередь ($K > 0$)**: Если все каналы (приборы) заняты, заявки поступают в очередь ограниченной вместимости. Заявка, пришедшая в момент, когда очередь полна, получает *отказ*.
2. **Нетерпеливость заявок**: Попав в очередь, заявка может "передумать" ждать. Максимальное время ожидания в очереди для каждой заявки генерируется по экспоненциальному закону с интенсивностью $\gamma$ ($T_{wait} \sim Exp(\gamma)$). Если заявка не успевает уйти на обслуживание до истечения этого таймера, она покидает систему (событие *Abandon*).

## Архитектура модели

Для создания расширяемой симуляции используются классы в `main.js`:

- `Request` (Заявка):
  - Содержит идентификатор (`id`), время прихода (`arrivalTime`), предел времени ожидания (`abandonTime`) и статус жизненного цикла (`NEW`, `IN_QUEUE`, `SERVING`, `SERVED`, `REJECTED`, `ABANDONED`).
- `Server` (Канал/Прибор обслуживания):
  - Содержит состояние занятости (`isBusy`) и ссылку на обслуживаемую в данный момент заявку. Методы `startService` и `finishService` управляют внутренней логикой.
- `EventQueue` (Очередь событий):
  - Приоритетная очередь будущих событий (ARRIVAL, DEPARTURE, ABANDON). Обеспечивает корректный порядок течения времени при симуляции дискретных событий.

## Ход процесса и метрики

- В ходе симуляции система ведёт регистрацию и строит лог изменения состояний приборов и размера очереди.  
- На выходе визуализируется диаграмма, отображающая доли событий для всех поступивших заявок:
  - **Обслужены** — достигли прибора и успешно отработаны.
  - **Отклонены** — сервер занят, а очередь была заполнена при поступлении заявки.
  - **Ушли (не дождались)** — попали в очередь, но истекло время терпения ($\gamma$).
